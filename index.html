04 — Case study

A messaging platform 300 services depend on.

At SS&C Intralinks I architected and own the multi-region event backbone behind 300+ microservices. Three problems define the work:

01 · Change

Change schemas without downtime

Led zero-downtime schema migrations with full backward compatibility, so services kept working while changes rolled out.

02 · Failure

Handle failure reliably

Redesigned retry strategies and dead-letter handling so transient faults heal themselves and poison messages are isolated, inspectable and replayable.

03 · Visibility

See problems before users do

Improved monitoring and alerting (Prometheus, Grafana) so problems surface early, which reduced production incidents.
